# 1.0.5 → 1.0.6 — Tool labels and mission title (unreleased)

## Breaking

- Every tool trigger of a `ToolModule` declares `display_name` as a plain class variable. A missing one raises
  `TypeError` when the module class is defined, so at import ([module authoring](../module_authoring.md)).
- `RegistryObjectToolKit.__init__` takes a required keyword `display_name`. A custom manager subclass must pass it.
- `TOOL_CALL_START.toolCallName` of a manager call is the function name the LLM called (`services_manager`), no longer
  `<manager>_<action>` (`services_manager_create`). A front that matched on the suffix reads the action from
  `metadata.functionDisplayName` or from the arguments instead ([tool labels](../agui_events.md)).
- `ServicesConfig` registers an SDK-owned `mission` storage collection (`MissionRecord`) on every module. A module that
  already uses a `mission` collection must rename it.
- `services_manager.update` requires `structure`, as `create` does (DEV-897). An update rewrites the whole content, so it
  must describe it; `{}` is still accepted. A call without it now fails with a validation envelope instead of cutting a
  revision with no map.

## Added

- `toolDisplayName` / `functionDisplayName` in `TOOL_CALL_START.metadata` and in the state entry `tools.<id>`. They are
  built from the toolkit map the HITL runner hands to `AgnoStreamAdapter(toolkits=...)`. An adapter built without
  `toolkits` only sends the humanized `toolDisplayName`.
- `AgnoStreamAdapter.set_toolkits(toolkits)`: the HITL runner keeps one adapter across auto-continues and refreshes
  its toolkit map on each, so a toolkit loaded by `load_manager` is labelled on the continue that follows.
- `AgUiMixin.mission_title(context)` hook and the `mission_title` custom event, emitted at most once per mission
  ([contract](../agui_custom_events.md#mission-title)).
- `DIGITALKIN_AGUI_MISSION_TITLE_ATTEMPTS` (default 3) and `DIGITALKIN_AGUI_MISSION_TITLE_TIMEOUT` (default 15 s).
- `metadata.model` on `TEXT_MESSAGE_START`, `REASONING_START` / `REASONING_MESSAGE_START` and `TOOL_CALL_START`: the
  LLM that produced it, and `metadata.requestedModel` when a LiteLLM fallback replaced the requested model
  ([models](../agui_events.md#models)). `SafeLiteLLM` reads the served model group from the proxy's response headers
  into `provider_data`; the events carry it as `model: ModelInfo`.
- `services_manager` actions `patch` and `append` (DEV-897): edit one element of a service's configuration by key path
  and value, without resending the whole JSON. `patch` replaces an element that exists and refuses a missing path;
  `append` adds a missing key (creating its parent objects) or pushes onto a list, and refuses to overwrite. Both cut a
  new version from the current one, or from `setup_version_id`, and carry over its name and documentation. Like
  `create`, both require `structure`: the entries describing the element they write, which replace every stored entry
  at or under the edited path (dropped entries are logged); entries elsewhere are kept. A `structure` key that is not
  the written element or a key inside it, or that does not resolve in the edited content, is refused before any write.
  Paths take no negative list index. No wire change: the SDK merges and sends a full `UpdateSetup` revision, so two
  concurrent edits of one service keep only the last.
- `services_manager` action `remove` (DEV-897): take one key or list item out of a service's configuration by key path,
  without resending the whole JSON; `delete` still removes the whole service. The path must exist. It takes no
  `structure`: the element's map entries are dropped, and removing a list item renames the entries of the later items
  of that list down one index (each renamed entry is logged). Same version handling as `patch` and `append`.
- `JsonStructure.patch`, `JsonStructure.append`, `JsonStructure.remove` (in-place edits), `JsonStructure.prune` (drop
  the map entries of one element), `JsonStructure.misplaced` (entries that do not describe it) and
  `JsonStructure.forget` (the map after a removal), in the structure-map path grammar.

## Changed

- `ToolModuleInfo._extract_tools_from_schema` is public: `ToolModuleInfo.extract_tools_from_schema`.
