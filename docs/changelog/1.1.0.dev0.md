# `1.0.4` → 1.1.0.dev0 — The knowledge service

## Summary

An agent can now search the enterprise knowledge base its user connected — Google Drive, Notion,
and whatever the Context Platform supports next — through a native service strategy and one Agno
tool, with no setup to configure and nothing to wire in an archetype.

```python
citations = await context.knowledge.search("why did we change the Apollo pricing?")
for citation in citations:
    print(citation.title, citation.source_url, citation.snippet)
```

What the search reaches is what *this user* may read. The permission filter is compiled into the
query by the platform, so a module has no identity to pass, no filter to apply afterwards, and no
way to widen its own scope. `SearchRequest` carries no identity field at all: the mission travels
as the ambient `x-mission-id` metadata every outbound call already gets, and the Service Provider
resolves it into the user and organization the search runs for.

> No breaking change. Adding a mandatory `knowledge` argument to `ModuleContext` is source-compatible
> for every module, because `BaseModule` builds the context from `ServicesConfig.valid_strategy_names()`.
> Only code constructing a `ModuleContext` by hand needs the new argument.

## Added

### `knowledge` service (`src/digitalkin/services/knowledge/`)

- **`KnowledgeStrategy`** — the read-only port: `search(query, sources=None, limit=None)` returning
  `list[Citation]`. Read-only by design: sources are connected by the customer through the product,
  never by an agent.
- **`GrpcKnowledge`** — client onto the Service Provider's `ContextService` (`agentic-mesh-protocol`
  1.1.0). Registered as a **stateless singleton** alongside the registry: it holds no per-request
  state, so one client serves every mission.
- **`DefaultKnowledge`** — in-memory corpus seeded from the strategy config, so `mode=LOCAL` sandboxes
  and unit tests answer deterministically offline:

  ```python
  services_config_params = {
      "knowledge": {"config": {"documents": [
          {"document_id": "doc_1", "title": "Pricing", "snippet": "Apollo moved to per-seat.",
           "source": "google_drive", "source_url": "https://..."},
      ]}}
  }
  ```

- **`Citation`** / **`Modality`** (`models/services/knowledge.py`) — one citation per matching
  document, carrying the passage that matched, the URL of the original, and a `locator`
  (`index`, `start`, `end`, `heading_path`).
- **`KnowledgeSettings`** (`DIGITALKIN_KNOWLEDGE_*`) — `search_timeout_s` (10 s, tighter than the
  global gRPC deadline) and `default_limit` (10 documents).

A request is clamped to the protocol's own bounds before it is sent (query ≤ 4000 characters,
≤ 16 sources, limit in 1–50), so an over-eager caller gets an answer instead of an
`INVALID_ARGUMENT` round-trip. An empty query raises `ValueError` without reaching the server —
a permanent condition must not be wrapped as a retryable service error.

### `knowledge_tools` Agno toolkit

`KnowledgeTools` exposes a single tool, `search_knowledge_base(query, sources=None, limit=10)`, and
is part of `DefaultToolkits.build(...)` — so every archetype that uses the default toolkits has it,
Ada included, with no change on their side.

What it hands the model is deliberately trimmed: `document_id`, `title`, `passage`, `source`,
`source_url`, and `section` when the document has headings. **`score` is never shown** — it is a
fused rank comparable only within one answer, and a model given a number reads it as a confidence.

An empty result is reported as a *success with zero results*, not an error, so the agent says
"nothing found" instead of retrying. A failure never raises into the agent loop and never echoes the
backend's own message.

## Changed

- **`agentic-mesh-protocol` 1.0.2 → 1.1.0**, which adds `agentic_mesh_protocol.context.v1`.
- **`ModuleContext`** gains `knowledge`, closed on cleanup unless borrowed.
- **`ModuleServer`** injects the Service Provider's client config for `knowledge` the way it already
  did for the registry — both are platform machinery served by that same provider — so an archetype
  configures nothing. `_prepare_registry_config` is renamed `_prepare_platform_configs` (private).
- **`healthcheck_services`** reports `knowledge` among the services it probes.
- **`.env.exemple`** regenerated with the two `DIGITALKIN_KNOWLEDGE_*` settings.
