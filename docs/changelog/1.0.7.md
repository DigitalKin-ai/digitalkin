# 1.0.6 → 1.0.7 — Functions per tool setup (unreleased)

## Added

- `SetupTool` and `SETUP_TOOLS_KEY` (`digitalkin.models.module`): a tool module lists, in a setup's content, functions
  that only this setup offers, e.g. the tools of the MCP server it connects to. Agents get them as functions of that
  setup when they resolve it, next to the module's triggers ([functions per setup](../module_authoring.md#functions-per-setup)).
- `ToolDefinition.trigger`: the module trigger serving a setup function; `ToolDefinition.enabled_by(triggers)` applies a
  tool selection to module triggers and setup functions alike.
- `ToolModuleInfo.from_module_info(..., setup_config=...)` and `ToolModuleInfo.setup_tool_definitions(...)`.

## Fixed

- `SetupInfo.config` from the gRPC registry holds plain Python values. Lists and objects nested in a setup's content used
  to stay protobuf `ListValue` / `Struct` containers.

## Migration

- Nothing to change for modules without setup functions.
- Code filtering `ToolModuleInfo.tools` by enabled trigger names should call `tool.enabled_by(enabled)` instead of
  `tool.name in enabled`, or it drops every setup function.
