# 1.0.6 → 1.0.7 — Run error codes, AG-UI 1.0 run endings and large services (unreleased)

## Breaking

- `RUN_ERROR.code` and `SUBAGENT_ERROR.code` are `RunErrorCode` values (`models/events/run_error_code.py`):
  UPPER_SNAKE, append-only, listed with their meaning in [RUN_ERROR codes](../gateway_protocol.md#run_error-codes).
  The free-form values are gone:

  | Before                                          | Now                                                           |
  |-------------------------------------------------|---------------------------------------------------------------|
  | `module_error`                                  | `MODULE_FAILED`                                               |
  | `permission_denied`                             | `PERMISSION_DENIED`                                           |
  | `cancelled`                                     | no `RUN_ERROR`: see the user stop below; `RUN_INTERRUPTED`     |
  | `partial_tool_results`                          | `TOOL_RESULTS_PARTIAL`                                        |
  | `auto_continue_limit`                           | `AUTO_CONTINUE_LIMIT`                                         |
  | `INPUT_VALIDATION_ERROR` (run input)            | `INPUT_INVALID`                                               |
  | agno slugs (`input_check_error`, …)             | `INPUT_REJECTED`, `OUTPUT_REJECTED`, `MODEL_*`, `UNKNOWN`      |
  | litellm exception names                         | `MODEL_*` codes, classified by `SafeLiteLLM.error_code`       |

- `RunErrorEvent.error_type` and `SubagentErrorEvent.code` are typed `RunErrorCode` and default to `UNKNOWN` instead of
  `None`. A trigger that builds them with a free string fails validation.
- `ModuleCodeModel.code` sent by `BaseModule` is `MODULE_FAILED`, `MODULE_INIT_FAILED` or `PERMISSION_DENIED` (was
  `Error` / `PermissionDenied`).
- A run the user stops (cancel or stop signal) no longer ends on `RUN_ERROR`. It ends on `RUN_FINISHED` with
  `outcome: {type: "cancelled"}`, after the SDK closes what the run left open: text and reasoning messages, running
  tool calls (`TOOL_CALL_RESULT {"error": "run cancelled"}`), running subagents (`SUBAGENT_ERROR` `RUN_CANCELLED`).
  The state's `run.status` is `cancelled`.
- A task cancelled by the platform (shutdown, timeout, service error, unknown cause) ends on `RUN_ERROR`
  `RUN_INTERRUPTED`, retryable.
- `stream.cancelled.reason` carries the real cause (`signal_service_cancel`, `signal_service_stop`, `shutdown`,
  `timeout`, …) instead of `cancelled`.
- `AgUiRunState.fail(context, message, code, **fields)` lost its `status` argument: a failure is always `failed`.
  `AgUiRunState.cancel(context, reason)` ends a run stopped by the user.
- `services_manager.update` requires `structure`, as `create` does (DEV-897). An update rewrites the whole content, so it
  must describe it; `{}` is still accepted. A call without it now fails with a validation envelope instead of cutting a
  revision with no map.
- `services_manager` writes (`create`, `update`, `patch`, `append`, `remove`) answer a `ServiceReceipt` — `setup_id`,
  `setup_version_id`, `version`, the written `path` (an appended list item's index) and `content_chars` — instead of
  the whole setup (DEV-937). Read the configuration back with `load`, the name and documentation with `get`. `tools`
  and `kins` managers are unchanged. `set_version` answers the same receipt for the activated version, with an empty
  `path`, instead of its whole configuration (`SetServiceVersionAction`); `tools` and `kins` `set_version` are
  unchanged.
- `SafeLiteLLM` sends `num_retries=0` to litellm, so the OpenAI client no longer resends a failed request by itself
  (DEV-937). `SafeLiteLLM` resends once, after `delay_between_retries`, a connection error, 429 or 5xx, and never a
  timeout: a request the proxy cut at 120 s (504) used to be resent twice unchanged, 6 minutes for the same failure.
  Transient failures get one resend instead of the client's two.
- `services_manager` `get` answers a service without its configuration: `current_setup_version` carries
  `content_chars` instead of `content` (DEV-938). Read the configuration with `load`. `tools` and `kins` `get` are
  unchanged.
- `services_manager` `load` never returns a part larger than `DIGITALKIN_SERVICES_MANAGER_LOAD_PAGE_CHARS` (default
  20 000) JSON characters whole (DEV-938, DEV-949): without `offset` / `limit` such a part is refused with its kind and
  size; with them it answers one page (`{page, offset, total, next_offset}`) of a list, a text or an object. A
  `limit` never returns more than one page. Paging a scalar is refused.
- `services_manager` `structure` and `get` refuse a map larger than `DIGITALKIN_SERVICES_MANAGER_STRUCTURE_MAX_CHARS`
  (default 20 000) JSON characters (DEV-949): page it with `structure` (`offset` / `limit`, `prefix`), find entries
  with `search_structure`, or call `get` with `structure=false`. A `search` row shows a text instead of such a map,
  so `structure` on a service row is a map or a string.
- `services_manager` `structure` reads the current version instead of the search index (DEV-949): a map written a
  moment ago is there, and a setup the index has no map for shows its stored one. `RegistryActionCtx.structure_of`
  is removed.

## Added

- `RUN_ERROR.metadata.retryable`: `true` when a later attempt can succeed, `false` when the same request fails again,
  absent when the SDK cannot tell (`RunErrorCode.retryable`). It sits in `metadata` because `RunErrorEvent` is a
  closed object in AG-UI 1.0.
- `SafeLiteLLM.error_code(exc)` classifies a litellm / openai failure into a `MODEL_*` code and raises
  `ModelCallError`; `AgnoStreamAdapter` maps agno's error types, and logs any it cannot map
  (`[VALIDATE RUN-ERROR-CODE-UNMAPPED]`) as `UNKNOWN`. A native agno model's `model_provider_error` carries no status
  code, so its wording decides (overflow, overload, rate limit, timeout, 400/403/404, outage); one that names no cause
  is `UNKNOWN`, which carries no retryable hint.
- `usage` on `RUN_FINISHED` (completed, paused or cancelled) and on `RUN_ERROR`: one AG-UI `TokenUsage` per provider
  and model, from the LLM calls the LiteLLM cost callback reports for the run's task while the run is open
  (`AgUiRunState.record_usage`, `CostTrackingLogger.token_usage`). Best effort: a call that started while the run was
  open but was reported after it closed is logged as `[VALIDATE AGUI-USAGE-LATE]`.
- `TaskSession.cancel_cause()`: why a task is being cancelled, readable while it still unwinds. `TaskSession` sets
  itself as `BaseModule.task_session`.
- Gemini's overflow wordings ("exceeds the maximum number of tokens", "token count exceeds") count as a context
  overflow in `SafeLiteLLM`: the prompt is compacted and resent, and a final failure is
  `MODEL_CONTEXT_LENGTH_EXCEEDED`.
- `services_manager` actions `patch` and `append` (DEV-897): edit one element of a service's configuration by key path
  and value, without resending the whole JSON. `patch` replaces an element that exists and refuses a missing path;
  `append` adds a missing key (creating its parent objects) or pushes onto a list, and refuses to overwrite. Both cut a
  new version from the current one, or from `setup_version_id`, and carry over its name and documentation. Like
  `create`, both require `structure`: the entries describing the element they write, which replace every stored entry
  at or under the edited path (dropped entries are logged); entries elsewhere are kept. A `structure` key that is not
  the written element or a key inside it, or that does not resolve in the edited content, is refused before any write.
  Paths take no negative list index. No wire change: the SDK merges and sends a full `UpdateSetup` revision, so two
  concurrent edits of one service keep only the last.
- `services_manager` action `remove` (DEV-897): take one key or list item out of a service's configuration by key path,
  without resending the whole JSON; `delete` still removes the whole service. The path must exist. It takes no
  `structure`: the element's map entries are dropped, and removing a list item renames the entries of the later items
  of that list down one index (each renamed entry is logged). Same version handling as `patch` and `append`.
- `JsonStructure.patch`, `JsonStructure.append`, `JsonStructure.remove` (in-place edits), `JsonStructure.prune` (drop
  the map entries of one element), `JsonStructure.misplaced` (entries that do not describe it) and
  `JsonStructure.forget` (the map after a removal), in the structure-map path grammar.
- `services_manager` action `generate` (DEV-938): write a configuration too large for one model call. The agent
  sends a `brief` and `sections` (`path`, `instructions`, `summary`); each section is written by its own call to a
  copy of the agent's model (bound by `DefaultToolkits.bind_host`), at most
  `DIGITALKIN_SERVICES_MANAGER_WRITER_CONCURRENCY`
  (default 4) at a time, then every section is merged into the current version and saved once. A section pushes
  onto a list, replaces an existing key or creates a missing one, and sets one structure entry at its path (a list
  that already has one keeps it). A reply
  that is not JSON is retried once; a section that still fails is listed in the receipt (`failed`: its index, path,
  instructions and reason, with a `hint`) and logged, the others are saved. A cancelled mission saves nothing.
- `services_manager` `append` takes `items` instead of `value` to push several list items in one call (the list is
  created when missing); its `structure` may describe the list once instead of each item.
- `services_manager` `load` takes `offset` and `limit` to page a list (items), a text (characters) or an object (keys,
  keys sorted). A text page is cut by `semantic-text-splitter` at the most natural boundary that fits (paragraph,
  sentence, word), sized as JSON so escapes count. `next_offset` is always the end of the page; the
  next page opens on the last `DIGITALKIN_SERVICES_MANAGER_TEXT_OVERLAP_CHARS` (default 500, at most a quarter of a
  page) characters of the previous one, from a word start, and its `offset` is its real start. `part` says which
  characters a page holds, how much it repeats and what follows (DEV-949). The `agno` extra now requires
  `semantic-text-splitter`.
- `services_manager` action `update_structure` (DEV-949): complete or correct a service's structure map without
  resending
  its configuration. Its `entries` (`{key path: description}`) are merged into the stored map (an empty description
  removes an entry); every described path must exist in the configuration, else nothing is written. Each call cuts
  a new version with the same content, name and documentation (the back offers no in-place edit of a version), so a
  large map goes in batches of about 100 entries. A `patch`/`append` refused for a structure key outside the written
  element now points at `update_structure`. `ServiceRevisionAction` is the new base of `ServiceEditAction` and
  `update_structure`.
- `services_manager` `get` takes `structure` (default true): `false` leaves the map out and gives its entry count,
  `structure_entries` (DEV-949).
- `services_manager` `structure` takes `offset` / `limit` (entries sorted by key path) and `prefix` (one branch:
  the entry at that path and every entry under it) (DEV-949).
- `services_manager` action `search_structure` (DEV-949): the map entries whose key path or description holds every
  word of `query`, case-insensitive, paged like `structure`.
- `ServicesManagerSettings` (`DIGITALKIN_SERVICES_MANAGER_STRUCTURE_MAX_CHARS`, `_LOAD_PAGE_CHARS`,
  `_TEXT_OVERLAP_CHARS`, `_WRITER_CONCURRENCY`), in `.env.exemple`.
- `ServicesManager.bind_writer(model)`, `JsonStructure.place` (push, replace or create at a path), `JsonStructure.page`
  (one page of a list or an object, bounded by count and JSON size), `JsonStructure.child` (a child's key path).
- `ToolError(message, retryable=None)` (`digitalkin.modules`): a trigger raises it for a failure the calling agent
  can act on. The SDK answers `MODULE_FAILED` with the message and logs it as a warning, without a traceback.
  `ModuleCodeModel.retryable` carries the hint, and the agent reads `Retrying may succeed.` or
  `Retrying the same call fails again.` after the message.
- `ToolHttpClient` (`digitalkin.modules`): the HTTP client of a tool module. One pooled `httpx.AsyncClient`, a
  timeout per attempt, resends with backoff (`Retry-After` first, capped by `max_retry_wait_s`) on 429 for every method
  and on 502/503/504, timeouts and transport errors for idempotent ones, a streamed `max_bytes` cap, and an optional
  `ssrf_guard` that refuses non-public addresses on every hop (the first included, up to `max_redirects`), and
  HTTP/2 when the server offers it. Every failure is a `ToolError` naming the
  service, method and path, never the query string: 408/425/429/5xx and transport errors retryable, other statuses
  not; override `status_failure` to add service guidance. `Retry-After`, `RateLimit-Reset` and
  `X-RateLimit-Reset-In` set the wait. Calls are logged with status, duration and attempt; resends and retryable
  failures as warnings, other failures at info. `httpx` is now a core dependency.

## Changed

- `services_manager` writes on one service (`update`, `patch`, `append`, `remove`, `generate`) run one after the
  other within a process (DEV-938): a per-service lock covers each read-modify-write, so two parallel edits both land
  instead of the last one overwriting the other. Across processes the last write still wins.
- `services_manager` `append` of a text onto an existing text adds it at the end (DEV-938); it used to be refused.
- Every write action of the registry managers (`create`, `update`, `patch`, `append`, `remove`, `update_structure`,
  `generate`, `delete`, `change_visibility`, `set_version`) states its scope in its description: which part of the
  service it changes (configuration at a path, whole configuration, structure map, name, documentation, visibility,
  active version) and which it keeps, so the model picks the action that touches only what it means to change.
- `services_manager` writes refuse a text a model escaped a second time — `\n` or `é` written out as characters
  instead of a real line break or accent (an all-ASCII text with no real line break holding a `\uXXXX` or at least two
  `\n`) — in `content` (create, update), `value` (patch, append) and `items` (append); `generate` reports such a
  section as failed. Seen on 5 of 5 appends of one magicbox mission, stored with `success:true`. `value` is now typed
  (string, number, boolean, array, object or null) instead of free (`SetupContentValidator.reject_escaped_text`).
- `services_manager` `generate` writers stream their section (the writer is still the agent's model, its reasoning
  settings untouched). The gateway in front of the LiteLLM proxy cuts a call that sends nothing for 120 s, and a
  section written as one block was silent until its end; streamed, it can be kept alive by the proxy's SSE keepalive
  pings (`sse_keepalive_ping_interval_seconds`), which only reach streamed calls. Only the reply's text is kept in
  the section, never its reasoning. A writer model must implement `ainvoke_stream`.
- `services_manager` reads a list index joined with "." the grammar's way: `items.0.title` is stored and edited as
  `items[0].title` (`JsonStructure.canonical`). Gemini writes the dotted form; `create` and `update` stored map keys
  the backend could not resolve, and `patch`, `append`, `remove` and `update_structure` refused the path as not found.
  A digit key becomes an index only where the configuration holds a list, so an object key `"0"` stays a key.
- `services_manager` `load` of a text estimates "about N more pages" from a full page's advance. A page ending early
  on a paragraph used to divide the rest of the text by a few characters ("about 2254 more pages").
- `SafeLiteLLM` classifies an SSE error frame by its `code` (DEV-981). Once the LiteLLM proxy has sent a keepalive
  ping, a failure reaches the client as an error frame under a 200, which litellm reports as a stream dropped before
  its first chunk; `SafeLiteLLM` resent every such drop once. A timeout frame (408, 504) or a rejection (4xx but 429)
  is now raised at once, so a proxy timeout costs its limit once, not twice; a rejection blaming the images is resent
  without them; a 429 or 5xx frame is still resent once.
- `SafeLiteLLM`: a streamed call that fails, or lasts a minute or more, logs what it received (`StreamProgress`: first
  chunk, longest silence, text, reasoning and tool-call argument sizes, request size), so a
  proxy timeout tells whether the call was silent from the start or writing.
- `services_manager` writes staged with `set_as_current=false` (`update`, `patch`, `append`, `remove`) answer the
  version they cut, read from the version history, instead of the version still served; `set_version` on the
  receipt's id now activates the staged edit.
- The escaped-text check runs on `services_manager` writes only (`create`, `update`, `patch`, `append`, `generate`),
  no longer on every manager's `content`, and each of them takes `literal_escapes` (default false): true keeps a text
  whose backslash sequences are meant (code, a Windows path, a regex), which the check refused with no way through.
- `generate` refuses a section lying inside another one (`catalog.products` with `catalog`) before any writer call,
  and fails a second section on one value that is not a list instead of letting it replace the first. A failed
  section gives `at`, the index its slice belonged at in its list; `ServiceSection.at` inserts a redone slice there,
  so the list keeps its order (redone neighbours too). The writer limit
  (`DIGITALKIN_SERVICES_MANAGER_WRITER_CONCURRENCY`) holds per process instead of per call.
- `services_manager` `load` keeps every text page within its JSON budget: the overlap is measured as JSON (a quarter
  page at most), and a tail the splitter returns whole is cut on a word boundary. Object pages follow sorted keys,
  since a stored object comes back in a different key order from one read to the next.
- A mission keeps the user's request of a run that never ended normally (DEV-982). Agno saves a run only when it
  ends and leaves an errored or cancelled run out of the history, so a first run cut by a timeout, a cancel or a
  crash left the next run with no history ("you had an error, try again" found nothing). `AgnoHitlRunner.run` now
  stores the request as its own run (`<run_id>:request`) on the run's first event, and drops it once the run is
  stored completed or paused (`StorageDb.keep_request`, `StorageDb.release_request`).
- `StorageDb.upsert_session` no longer stores an assistant message with no text and no tool call (DEV-978): it was
  stored at every save, then dropped from every request.
- A provider refusal (`finish_reason: content_filter`) in a stream is raised once the stream has ended (DEV-978):
  raised mid-stream, it left litellm's response open (`Unclosed client session`).
- The compaction summary model sends no prompt cache breakpoints (`SafeLiteLLM.from_spec(prompt_caching=False)`,
  DEV-977): one call per summary wrote its whole input to the cache, never read back, at a higher price than input.
- A kin's tool selection saved before its tool renamed or added triggers turns the triggers it never saw on, as the
  tool's selection schema defaults them (DEV-975): a selection naming a trigger the tool no longer exposes next to
  one it still does (`ToolSelection.predates`) gets every trigger absent from it on (`ToolSelection.enabled`),
  logged with `[VALIDATE TRIGGER-DEFAULT-ON]`. A trigger set to false stays off, a selection with current names only
  keeps its scope, and one sharing no name with the tool stays closed. The RAG kin whose `search` became
  `search_documents` could no longer search its documents.
- A tool selection enabling the SDK's utility protocols (`healthcheck_*`, `UtilityProtocol.protocols()`) no longer
  reports them as triggers the module does not expose (DEV-975); only stale trigger names are.
- A setup's content reads its whole numbers back as int (`SetupVersionData`): the setup service carries the content
  as a protobuf Struct, so a stored `1` arrived as `1.0`, and a model reading a service saw `"id": 1.0`. A whole
  number beyond 2**53 stays a float, as in storage.
- `SafeLiteLLM` reads an SSE error frame's code past a second drop wrapper, so a timeout frame litellm wrapped twice
  is not resent.

## Fixed

- LLM cost: a cache write was billed twice, once at the input price inside `chatbot_input` and once at its own price
  in `chatbot_cache_creation_input`, because litellm's `prompt_tokens` already counts cache writes. `chatbot_input`
  now holds only the input that is neither read from nor written to the cache.
- `SetupInfo.config` from the gRPC registry (`get_setup`) holds plain Python values at every level. `dict()` only
  converted the top level, so lists and objects nested in a setup's content stayed protobuf `ListValue` / `Struct`
  containers. Numbers stay floats, as before. A NaN or infinite number is still kept as a float, as `dict()` kept it,
  and is now logged with the setup and its path: JSON has no such value, so a later serialization rewrites it
  (`null` from pydantic) or emits invalid JSON.
- A tool trigger that raised reached the calling agent as `No successful response received from module`: the
  `ModuleCodeModel` frame it sends has no `root`, and `ModuleToolkit` and the plain tool function skipped it. Both
  now fail the call with `[CODE] message`, so the agent reads why the tool failed. The message of any exception is
  `<Type>: <text>` and goes through `ToolError.redact`, which masks URL query strings and `api_key=` / `token:` /
  `Authorization` values: a library error such as httpx's `Client error '401' for url '…?api_key=…'` no longer
  carries the key.
- `AgUiRunInput` declares its fields as read-only properties, so the SDK's own `AgUiStreamInput` satisfies it under
  mypy (a mutable `tools: list | None` protocol member rejected its `tools: list`).
- Event and gRPC-server models declare their defaults as `Field(default=...)`: a positional `Field(<default>)` is not
  seen by mypy without the pydantic plugin, so `RunErrorEvent(content=...)` failed with `Missing named argument
  "event"` in a module's type check.

## Migration

- A consumer of `RUN_ERROR` switches on the new codes and reads `metadata.retryable`, and treats `RUN_FINISHED` with
  `outcome.type == "cancelled"` as a stop (keep the partial answer, no error).
- A trigger that emits `RunErrorEvent` / `SubagentErrorEvent` passes a `RunErrorCode`.
- A caller of `AgUiRunState.fail` drops the `status` argument.
- A tool trigger raises `ToolError` for a failure instead of returning it inside a normal output (an `error` field,
  `success=False`, a "failed:" text or an empty result): a returned output is read as a success.
