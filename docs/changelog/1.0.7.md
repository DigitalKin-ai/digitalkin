# 1.0.6 → 1.0.7 — Run error codes and AG-UI 1.0 run endings (unreleased)

## Breaking

- `RUN_ERROR.code` and `SUBAGENT_ERROR.code` are `RunErrorCode` values (`models/events/run_error_code.py`):
  UPPER_SNAKE, append-only, listed with their meaning in [RUN_ERROR codes](../gateway_protocol.md#run_error-codes).
  The free-form values are gone:

  | Before                                          | Now                                                           |
  |-------------------------------------------------|---------------------------------------------------------------|
  | `module_error`                                  | `MODULE_FAILED`                                               |
  | `permission_denied`                             | `PERMISSION_DENIED`                                           |
  | `cancelled`                                     | no `RUN_ERROR`: see the user stop below; `RUN_INTERRUPTED`     |
  | `partial_tool_results`                          | `TOOL_RESULTS_PARTIAL`                                        |
  | `auto_continue_limit`                           | `AUTO_CONTINUE_LIMIT`                                         |
  | `INPUT_VALIDATION_ERROR` (run input)            | `INPUT_INVALID`                                               |
  | agno slugs (`input_check_error`, …)             | `INPUT_REJECTED`, `OUTPUT_REJECTED`, `MODEL_*`, `UNKNOWN`      |
  | litellm exception names                         | `MODEL_*` codes, classified by `SafeLiteLLM.error_code`       |

- `RunErrorEvent.error_type` and `SubagentErrorEvent.code` are typed `RunErrorCode` and default to `UNKNOWN` instead of
  `None`. A trigger that builds them with a free string fails validation.
- `ModuleCodeModel.code` sent by `BaseModule` is `MODULE_FAILED`, `MODULE_INIT_FAILED` or `PERMISSION_DENIED` (was
  `Error` / `PermissionDenied`).
- A run the user stops (cancel or stop signal) no longer ends on `RUN_ERROR`. It ends on `RUN_FINISHED` with
  `outcome: {type: "cancelled"}`, after the SDK closes what the run left open: text and reasoning messages, running
  tool calls (`TOOL_CALL_RESULT {"error": "run cancelled"}`), running subagents (`SUBAGENT_ERROR` `RUN_CANCELLED`).
  The state's `run.status` is `cancelled`.
- A task cancelled by the platform (shutdown, timeout, service error, unknown cause) ends on `RUN_ERROR`
  `RUN_INTERRUPTED`, retryable.
- `stream.cancelled.reason` carries the real cause (`signal_service_cancel`, `signal_service_stop`, `shutdown`,
  `timeout`, …) instead of `cancelled`.
- `AgUiRunState.fail(context, message, code, **fields)` lost its `status` argument: a failure is always `failed`.
  `AgUiRunState.cancel(context, reason)` ends a run stopped by the user.

## Added

- `RUN_ERROR.metadata.retryable`: `true` when a later attempt can succeed, `false` when the same request fails again,
  absent when the SDK cannot tell (`RunErrorCode.retryable`). It sits in `metadata` because `RunErrorEvent` is a
  closed object in AG-UI 1.0.
- `SafeLiteLLM.error_code(exc)` classifies a litellm / openai failure into a `MODEL_*` code and raises
  `ModelCallError`; `AgnoStreamAdapter` maps agno's error types, and logs any it cannot map
  (`[VALIDATE RUN-ERROR-CODE-UNMAPPED]`) as `UNKNOWN`. A native agno model's `model_provider_error` carries no status
  code, so its wording decides (overflow, overload, rate limit, timeout, 400/403/404, outage); one that names no cause
  is `UNKNOWN`, which carries no retryable hint.
- `usage` on `RUN_FINISHED` (completed, paused or cancelled) and on `RUN_ERROR`: one AG-UI `TokenUsage` per provider
  and model, from the LLM calls the LiteLLM cost callback reports for the run's task while the run is open
  (`AgUiRunState.record_usage`, `CostTrackingLogger.token_usage`). Best effort: a call that started while the run was
  open but was reported after it closed is logged as `[VALIDATE AGUI-USAGE-LATE]`.
- `TaskSession.cancel_cause()`: why a task is being cancelled, readable while it still unwinds. `TaskSession` sets
  itself as `BaseModule.task_session`.
- Gemini's overflow wordings ("exceeds the maximum number of tokens", "token count exceeds") count as a context
  overflow in `SafeLiteLLM`: the prompt is compacted and resent, and a final failure is
  `MODEL_CONTEXT_LENGTH_EXCEEDED`.

## Fixed

- LLM cost: a cache write was billed twice, once at the input price inside `chatbot_input` and once at its own price
  in `chatbot_cache_creation_input`, because litellm's `prompt_tokens` already counts cache writes. `chatbot_input`
  now holds only the input that is neither read from nor written to the cache.
- `SetupInfo.config` from the gRPC registry (`get_setup`) holds plain Python values at every level. `dict()` only
  converted the top level, so lists and objects nested in a setup's content stayed protobuf `ListValue` / `Struct`
  containers. Numbers stay floats, as before. A NaN or infinite number is still kept as a float, as `dict()` kept it,
  and is now logged with the setup and its path: JSON has no such value, so a later serialization rewrites it
  (`null` from pydantic) or emits invalid JSON.

## Migration

- A consumer of `RUN_ERROR` switches on the new codes and reads `metadata.retryable`, and treats `RUN_FINISHED` with
  `outcome.type == "cancelled"` as a stop (keep the partial answer, no error).
- A trigger that emits `RunErrorEvent` / `SubagentErrorEvent` passes a `RunErrorCode`.
- A caller of `AgUiRunState.fail` drops the `status` argument.
